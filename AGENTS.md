# Инструкции для агентов ACatalog

## Цель

ACatalog — каталог self-hosted приложений и сервисов. Основной пользователь ищет замену SaaS или сервис для домашней инфраструктуры, сравнивает варианты и открывает официальный источник/Compose-файл.

## Состояние проекта

Рабочий Vue-каталог, pipeline импорта, тесты, CI и production Docker-конфигурация реализованы. Перед изменениями проверять фактические команды в `package.json` и эксплуатационные правила в `docs/OPERATIONS.md`.

## Структура данных

- `raw/` — внешние Git-клоны и исходные материалы. Не редактировать вручную и не перезаписывать при генерации каталога.
- `raw/deployments/` — минимальные клоны официальных репозиториев приложений с найденным Compose; управляются `npm run data:deployments`.
- `data/` — нормализованные данные ACatalog и локальные ассеты.
- `data/icons/` — иконки приложений, предпочтительно WebP 512×512.
- `data/logo/` — брендовые материалы ACatalog или внешние логотипы, если появится обоснованная необходимость.
- `docs/` — проектные решения и план реализации.

Каждая запись каталога обязана иметь provenance:

- источник (`raw/<repo>`);
- название исходного репозитория;
- URL исходного Git-репозитория;
- commit SHA или ref, на котором выполнен импорт;
- путь к README/Compose-файлу внутри источника;
- дату импорта и статус валидации.

## Импорт и нормализация

Импорт должен быть воспроизводимым и идемпотентным. Парсер обязан:

1. извлекать название, описание, категорию, URL сайта, GitHub URL, лицензии и поддерживаемые способы запуска;
2. сопоставлять Compose-файлы с приложением, не выдавая случайный соседний пример за официальный;
3. сохранять ссылку на исходный путь, а не только скопированный текст;
4. помечать неоднозначные или неполные поля, а не додумывать их;
5. не удалять существующие записи без отчёта об изменении.

Иконки: сначала favicon официального сайта, затем согласованный fallback. Для каждого файла сохранять исходный URL, дату загрузки и лицензионную заметку. Не использовать emoji в интерфейсе вместо иконок.

## UI и UX

Использовать готовую дизайн-систему `shadcn-vue` и Lucide. Не создавать отдельную самодельную систему компонентов без необходимости. Соблюдать выбранное направление Minimalism & Swiss Style:

- чистая сетка и заметная иерархия;
- IBM Plex Sans для UI, JetBrains Mono для кода и метаданных;
- контраст текста не ниже WCAG AA;
- видимый focus-state и полная клавиатурная навигация;
- кликабельные области не меньше 44×44 px;
- уважать `prefers-reduced-motion`;
- резервировать место под иконки, чтобы избежать layout shift;
- не использовать hover как единственный способ показать действие.
- мобильная и пк верися.

## Технические правила

- Vue 3 Composition API, TypeScript strict mode.
- Не смешивать сетевой импорт, нормализацию и UI-рендеринг в одном модуле.
- Все внешние URL валидировать и открывать безопасно.
- Поиск должен учитывать название, описание, категории, теги и алиасы.
- Сортировку stars считать вторичной к релевантности; отсутствие stars не должно превращаться в ноль без явного правила.
- Docker Compose показывать как текст из проверенного источника, с кнопкой копирования и ссылкой на исходный файл.
- Сохранять понятные ошибки и состояние пустого результата поиска.
- Перед merge запускать typecheck, unit-тесты, сборку и Playwright smoke-тесты.

## Запрещено

- выдумывать официальные сайты, GitHub-ссылки, stars, лицензии или Compose-файлы;
- терять provenance при преобразовании raw-данных;
- править файлы в `raw/` ради удобства фронтенда;
- добавлять изображения без проверки размера, формата, источника и лицензии;
- публиковать незаполненные placeholder-данные как реальные записи.
